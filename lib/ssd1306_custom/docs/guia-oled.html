El uso siempre sigue tres pasos

01

Preparar

Inicializás la OLED y configurás campos, barras o menú una vez.

02

Actualizar

Pasás la medición, el texto, el valor de la barra o el movimiento del menú. Eso modifica la imagen en RAM.

03

Mostrar

Llamás a ssd1306_show(&oled) después de preparar todo. No hace falta enviar cada elemento por separado.

Podés actualizar desde app_display_update() cuando le toque a la pantalla. La biblioteca no decide el período ni crea tareas; el envío por I²C es bloqueante y tiene timeout.

Lo mínimo para empezar

Inicializar la pantalla con los pines de tu placa
#include "ssd1306_widgets.h"

static ssd1306_t oled = {0};

bool display_init(void)
{
    i2c_init(i2c0, 400000);
    gpio_set_function(4, GPIO_FUNC_I2C); // SDA
    gpio_set_function(1, GPIO_FUNC_I2C); // SCL
    gpio_pull_up(4);
    gpio_pull_up(1);

    return ssd1306_init(&oled, 128, 64, 0x3C,
                        i2c0, SSD1306) == SSD1306_OK;
}

La instancia debe empezar en cero y permanecer válida. El driver reserva el framebuffer internamente; ssd1306_deinit() lo libera. El SDK y los pines se configuran en la aplicación.

¿Qué significan x, y, ancho, alto y escala?

El origen está arriba a la izquierda: x=0, y=0. En una OLED 128×64, las posiciones llegan hasta x=127, y=63. Un campo es un rectángulo reservado para texto. La escala 1 usa caracteres 5×8, la escala 2 los duplica. El campo completo debe entrar en la pantalla.

¿Qué pasa si el texto no entra?

Se dibuja la parte que entra y se devuelve SSD1306_ERR_TRUNCATED. Los campos usan ASCII imprimible: todavía no hay soporte UTF-8 para tildes o ñ. Para evitar restos, actualizá siempre el mismo campo en lugar de dibujar texto suelto encima.

¿Cómo conecto el encoder al menú de componentes?

Cuando detectás un paso del encoder llamás a ssd1306_menu_move(&menu, +1) o -1. Al presionar el botón, tu aplicación consulta menu.selected y abre la pantalla elegida. La biblioteca no lee GPIO ni modifica ganancias del PID.

¿Qué faltaría para que sea todavía más fácil?

Esa capa ya está implementada como ssd1306_screens. La siguiente ampliación posible sería persistir configuraciones en flash o agregar otros diseños. La capa actual resuelve distribución, navegación, edición y detección de cambios; tu aplicación conecta sensores, encoder y lógica del motor.
